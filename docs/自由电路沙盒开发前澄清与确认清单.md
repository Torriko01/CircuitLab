### C2 的器件承诺需要特别明确

“能在原生菜单中找到某种元件”“当前课程验证过某种等效模型”“沙盒中任意画法和所有型号模型都已验证”是不同层次。首版应列出已验证的器件和代表电路。高级器件可保留探索入口，但不能把整个原生器件库统一标成工程验证通过。

这里不预先承诺固定元件数或整板容量。具体支持规模由性能预研和验收确定。若你已有首版必须分析的电路类型，可优先替换或扩充首批用例。

### C4/C5 的推荐操作语义

| 操作 | 推荐行为 |
|---|---|
| 新建、载入项目 | 保持暂停；确认连接和初始条件后运行 |
| 暂停 → 继续 | 在同一次内存运行中继续，不主动清零电容/电感状态 |
| 切换开关、逻辑输入 | 作为本次运行的激励，观察连续瞬态；相关状态变化需要纳入运行条件 |
| 改连线、元件值、源参数 | 暂停；旧结果不再代表新设计；要求明确重新开始 |
| 仅移动元件、修改文字或改变显示设置 | 更新文档或视图，不应仅因位置变化清空电气状态；若移动同时改变连接，按改图处理 |
| 重新开始 | 仿真时间归零，保留当前开关/逻辑输入设置，按设计中声明的电容电压、电感电流等初始条件启动；不等于全部强制为零 |
| 离开沙盒、切换项目、页面隐藏 | 保存已完成修改并暂停；返回后保持暂停，不自动运行 |
| 关闭后重开项目 | 恢复设计与约定的视图配置；不承诺恢复关闭瞬间的运行状态和历史波形 |

推荐将当前开关位置/逻辑输入作为当前项目设置保存，重开时沿用最后一次已保存的设置；暂停和重新开始都不自动把开关拨回旧位置。运行中切换属于激励，不能据此假定整段历史波形是在同一静态开关条件下生成；需要将激励变化与其他电气修改区分。首版不另做开关操作回放或跨会话恢复时间轴。此行为随 C4/C5 一并确认。

### C6 的保存边界

本机项目库与学习进度分开。浏览器存储按来源隔离：开发端口、生产端口，或 `localhost` 与 `127.0.0.1` 不应被当作同一个项目库。交付包不自动包含个人浏览器中的项目，跨环境靠项目文件导出/导入。

推荐自动保存当前项目，另存副本用于主动保留版本；首版不做完整版本历史。只有实际写入成功后才能显示“已保存”。存储失败时保留内存编辑并提供导出；不把草稿自动保存宣传成文件备份。

导入默认新建副本，避免同 ID 文件意外覆盖原项目。可解析但不收敛的电路仍允许作为草稿保存；解析失败、未知关键元件或不支持的文件不能以“成功”替换当前图。

## 4. 可以沿用的工程约定

以下是建议由开发者落实的常规选择，用户无需决定存储 API、前端状态库或文件扩展名：

- 保留 React/TypeScript/Vite 和固定 CircuitJS，沙盒使用独立页面、适配器和项目类型。
- 课程 `Store/schema 4` 与沙盒项目分开；是否升级应用展示版本，不等于修改课程记录格式。
- 项目库优先 IndexedDB，导出文件带明确格式与内核版本；记录原生文档，避免重写整个电路解析器。
- 明确区分文档版本、电气设计版本和单次运行。视图变化、纯位置变化、运行激励不能一律当成同一种电气重置。
- 导入在临时上下文验证后提交；失败不替换当前项目；错误电路可以继续保存和编辑。
- 原生控件与中文外层共用运行状态；高级原生入口若不能接入项目规则，应明确限制或后置，不能悄悄绕过。
- 保持项目现有许可证、来源与可复现构建记录。正常开发修复和验证不需要再次逐项审批。

若技术验证证明不能满足已确认行为，不应自动删减需求或换路线；应带着结果、可行替代和影响再次讨论。

## 5. 工期与验收还有什么没有冻结

原评估的 **6–10 人日是范围受限的粗估**，尚非固定工期。尤其“区分热操作和设计修改”“保留示波器但排除运行状态”“统一原生多个载入入口”都需要验证。

产品约定确认后，先做第一阶段技术预研与最小原型，形成能力矩阵，再冻结详细设计、任务分解和验收容差。若要求全中文编辑器、所有器件保障、完整运行恢复或首版通用测量，应重估，不沿用原粗估。

交付门槛应包括：完整鼠标搭建、代表电路的独立数值与步长核验、操作状态、文件/草稿恢复、异常恢复、浏览器交互与课程回归。现有 897 次课程捕获、4481 项检查保留为旧模型证据，不转换成沙盒已验收。
