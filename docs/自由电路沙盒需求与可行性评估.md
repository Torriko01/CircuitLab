# 自由电路沙盒需求与可行性评估

日期：2026-10-15。评估基线：MVP 0.4、十二门固定电路课程，以及项目内固定版本的 CircuitJS。本文保留需求评估时的分析；沙盒现已作为 v0.5 集成到工作台，实际结果见[沙盒验收报告](./沙盒验收报告-v0.5.md)。

决策更新：用户已选择方案 B，并确认 C1–C8 全部推荐约定。开发基线见[澄清与确认清单](./自由电路沙盒开发前澄清与确认清单.md)，模块设计和完成情况见[详细设计与项目计划](./沙盒详细设计与项目计划-v0.5.md)。

## 1. 结论

**可以在现有项目上增量实现一个可用的自由电路沙盒，不需要更换仿真内核。** 推荐新增独立的“自由实验室”，复用 CircuitJS 原生绘图和示波器，由中文工作台补充项目保存、学习指引、状态提示和课程模板入口。

当前课程故意禁止编辑；底层内核已经具备编辑能力。开发重点是把编辑器接入完整学习流程，并保证改图后测量、保存与运行状态的含义清楚。单独将 `editable` 改为 `true` 可以演示编辑能力，但不能完成这条需求。

建议首版定位为：**绘制小规模教学电路 → 改参数或连接 → 运行观察 → 保存设计 → 换一个条件复测**。它适合培养读图、参考点、支路电流和时间尺度的感觉；对任意电路自动给出正确解释、自动评分、真实器件签核不在首版范围内。

## 2. 需求分析：用户真正要完成什么

现有课程能训练“在给定电路上定位问题”，自由沙盒补上“把自己的问题表达成电路”的能力，尤其适合通用 MCU 控制板、传感器与接口的局部分析。

| 用户任务 | 需要的能力 | 学习价值 |
|---|---|---|
| 从空白画一个分压、上拉或 RC | 放置元件、连线、接地、设数值、撤销 | 建立连接关系和电流路径的感觉 |
| 给课程电路接一个自己的负载 | 从正常教学模板创建独立副本 | 把课内结论迁移到未给定的条件 |
| 测量某两点的电压与元件电流 | 明确参考点、端点、方向、单位 | 避免把“节点电压”和“元件压差”混为一谈 |
| 修改电阻、电容、负载或激励 | 运行、暂停、重置、观察波形 | 学会控制变量，检查稳态和瞬态差异 |
| 关闭页面后继续，或分享电路文件 | 本地草稿、命名、重新打开、导入导出 | 形成可复现的个人实验积累 |
| 电路不工作时找到下一步检查方向 | 可见的求解错误与检查提示 | 练习查连接、参考、模型和时间设置 |

“绘制电路图”在这里指可参与仿真的原理图。PCB 封装、走线、层叠、电磁场与实物仪器控制是另外的需求。

为了与原学习目标一致，界面应保留简短的实验笔记：“我预测什么”“只改什么”“观察到什么”。先满足画、跑、看、存，再逐步加入自动对比和智能提示。

## 4. 为什么不能只打开编辑开关

### 4.1 改图会破坏课程测点与证据含义

现有适配器按元件数组下标取得支路，并校验预期类型；课程节点也来自预定义名单。用户新增、删除或重排元件后，下标和对象引用可能指向其他对象。继续显示旧读数，会比明确报错更误导。

沙盒必须使用独立的运行与测量生命周期。设计发生变化时，旧运行标记为历史；当前测点要重建或明确失效。首版优先使用原生示波器与元件信息，暂不接入课程的固定支路选择、诊断评分和证据达标规则。

### 4.2 原生导出不等于纯设计，也不等于完整运行存档

当前公开 `exportCircuit()` 调用默认的 `dumpCircuit(true)`：除了连接、参数与模型，还写入部分元件运行状态和示波器配置。因此：

- 仿真过程中原始导出字符串可能变化，不能直接把它的哈希当作“用户改图”的判定。
- 源码的 `dumpCircuit(false)` 排除运行状态及示波器，内部用于判断设计变化；目前没有作为公开 API 暴露。正式集成可增加一个很薄的桥接接口，并按照原生规则处理滑条等显示设置。
- 含部分状态的 XML 未经验证，不能承诺完整恢复仿真时刻、源相位和全部历史波形。

项目应区分设计版本、视图/示波器配置、显式初始条件、单次运行快照。默认复测从声明的初始条件开始；“继续当前运行”和“重新开始”要有不同含义。具体重置与往返行为需要用 RC 和电感电路验收，不能只靠直流分压例子推断。

### 4.3 命名节点不是无副作用的探针标签

固定版本的 `LabeledNodeElm` 会把同名节点电气连接起来。同名标签在自由电路中可能是有意连接，不能套用当前课程“每个名字必须唯一”的校验，也不能把添加标签仅当成给测点命名。

同样，公开元件对象没有可跨导入保持的稳定 ID；一个 `getCurrent()` 不能代表任意多端元件的所有引脚电流。后续统一测量面板需要建立测点、端口与方向的明确映射。首版中文指引应说明电压参考和电流正方向。

### 4.4 求解停止与用户暂停需要区分

公开 API 的 `isRunning()` 不能单独说明是用户暂停、测试结束还是求解错误。错误文本目前在内核内部和原生界面显示。工作台若要显示明确状态，应补充分析/错误状态桥接；`onanalyze` 表示重新分析，不是覆盖所有修改的稳定文档变更通知。

自由连接也会产生无效或难收敛的电路。首版需要保留可打开的设计、显示实际错误并允许修改恢复，不把失败或未完成结果展示成有效测量。

### 4.5 iframe 不是计算隔离

当前同源 iframe 便于接入 API，但不能保证复杂求解卡住时主界面仍可响应。父页面定时器也不能中断已阻塞的 JavaScript。现有课程的 15 秒捕获超时不能直接作为任意电路的硬终止保证。

首版按小规模教学电路设计，设置导入大小、记录样本、运行窗口等预算，并通过实际性能测试确定支持范围。若要承诺大电路和强制终止，需要单独评估 Worker 化等执行架构调整。

## 5. 方案选型

| 方案 | 做法 | 成本与优点 | 主要缺口 | 判断 |
|---|---|---|---|---|
| A：开放原生编辑页 | 新增入口，直接嵌入完整编辑器 | 最快验证，原生功能较全 | 项目管理、中文体验、恢复、课程衔接不足 | 适合能力演示 |
| **B：原生编辑器 + 中文项目工作台** | 独立沙盒页面，复用绘图/求解/示波器，补项目与状态管理 | 避免重复造编辑器；能形成画、跑、看、存闭环 | 需薄层 API 桥接和专项验收 | **推荐作为当前 MVP 的下一次增量** |
| C：完全自建编辑器 | 自行实现画布、吸附、旋转、连线、节点、撤销、序列化，再对接求解 | 体验控制力最高 | 图与电气拓扑一致性、器件端口、撤销和格式兼容工作量显著增加 | 暂缓，待原生交互成为明确瓶颈 |

本表的 A/B/C 是本次沙盒方案编号。推荐 B 仍延续项目原先选定的“路线 C：中文工作台集成现有仿真内核”，没有变更总体路线。

## 6. 建议首版范围

### P0：完成一个小而完整的沙盒

1. 独立“自由实验室”入口，支持空白项目和三个起步模板：分压与负载、RC、开漏上拉。三者贴近现有课程，且便于独立核验。
2. 复用原生工具放置、连线、修改、删除、撤销、重做和缩放。首批重点验收电阻、电容、电感、导线、地、电源、开关、二极管及受控开关；其他原生器件允许探索，但逐项标注模型边界与验证状态。
3. 运行、暂停、重新开始；电压颜色、电流动画、元件读数和原生示波器。指引说明动画速度/颜色范围是显示设置，不能当成真实电子运动速度或不经读数的量化依据。
4. 本地命名、保存、重新打开、另存副本、删除自己的项目；自动草稿和文件备份。导入失败保留原项目，存储失败有提示。
5. 导入/导出本项目支持的 CircuitJS 文档及版本化项目文件。导出原生格式按当前 XML 处理；本次只验证了旧文本分压样例导入，旧文本器件兼容范围需进一步验收；不宣称通用 SPICE 格式兼容。
6. 电路修改后重置运行关联；错误与未完成状态可见。记录实验问题、预测和观察，保存设计版本信息。

课程中的模板复制应创建新项目，保留来源课程与模型说明。首版先开放上述三课正常模板，后续再扩展十二课；不将隐藏诊断故障当作模板导出。

### P1：根据使用反馈扩展

- 所有正常课程电路一键复制到沙盒。
- 中文统一的差分电压、指定支路电流、游标与捕获面板。
- 两个版本的波形对比、CSV、波形截图和结构化实验笔记。
- 针对常见问题的检查提示：连接未落到端点、单位误填、参考点选错、时间窗口不匹配等。先做可验证规则，不先承诺通用智能诊断。

首版不包含 PCB 编辑、KiCad/任意 SPICE 模型互导、真实 MCU 固件联合仿真、多人协作和任意电路自动评分。运放、MOSFET、接口等器件的教学模型也不能自动替代具体型号的手册参数。

## 7. 对现有架构的建议改动

| 部分 | 建议 | 目的 |
|---|---|---|
| 导航和视图 | 新增 `SandboxPage` 与独立工作区状态 | 沙盒有自己的项目生命周期 |
| 仿真接入 | 新增 `SandboxAdapter`，保留 `CircuitAdapter` 服务固定课程 | 避免固定参数生成器重载时清空手绘内容 |
| 薄层内核桥接 | 设计导出/变更、载入完成、重置与运行/错误状态；保持数值求解算法 | 让宿主可靠判断保存与运行状态 |
| 类型 | 独立 `SandboxProject`、`SandboxRun`，不把沙盒塞入 `LessonId` 或 `Params` | 自由拓扑和课程预设有不同约束 |
| 本地存储 | 独立项目库，建议 IndexedDB；导出文件作为显式备份 | 避免挤占课程 JSON，也不依赖原生单份恢复记录 |
| 保存内容 | 项目格式版本、ID、名称、时间、来源、内核版本、原生文档、设计版本、初始条件说明和笔记 | 支持恢复、兼容判断和复现 |
| 运行内容 | 关联项目设计版本、起始快照、设置、结束状态；波形存储另设预算 | 不把旧运行误认为当前图的结果 |

原生导出文档尽量原样保留，以免丢模型定义；设计变更检测另用不含运行状态的表示。视图配置与初始条件的恢复要独立验证。不要依赖元件数组下标作为持久测点 ID，也不要仅凭运行停止判定测试成功。

导入对象限定为支持的电路/项目文档，设大小与结构校验并处理解析失败；没有必要提供任意网页或脚本上传。项目继续使用已固定并随包分发的 GPL 内核，无需引入另一个仿真服务。

## 8. 实施拆分与工作量判断

以下为单名熟悉现有代码的开发者、桌面浏览器优先、复用原生编辑和示波器的粗估。它不是交付日期承诺；移动端专门交互、自建编辑器、统一测量面板与完整波形存档不计入。

| 工作包 | 预计人日 | 完成判据 |
|---|---:|---|
| 编辑页嵌入、资源修复与生命周期预研 | 1–2 | 正确接管焦点；无侧栏缺失资源；证明设计变更与载入完成可检测 |
| 项目库、草稿、导入导出 | 1–2 | 刷新恢复；导入失败不破坏现有项目；能文件往返 |
| 运行、重置、错误/变更桥接 | 1–2 | 不混用不同设计的运行；异常可恢复；初始条件明确 |
| 三个模板和中文观察指引 | 1 | 每个模板可编辑、运行、观察并保存 |
| 数值、交互、存储和课程回归验收 | 2–3 | 通过下一节的门槛，记录真实兼容范围 |
| **合计** | **6–10 人日** | 可评审的首版闭环 |

第一工作包是技术闸门：如果稳定变更通知、运行错误状态或重置语义需要超出薄层桥接的改造，应重新估算，不能一边开放任意编辑一边继续使用课程的旧测点假设。

当前“小而完整”的目标下，优先实现以上闭环，之后根据你的实际手绘电路决定是否投入统一测量和更深中文化。

## 9. 验收门槛：功能可用与结论可信分别验证

| 验收项 | 方法与预期 |
|---|---|
| 从空白搭建 | 实际鼠标放源、两电阻、地并连线；不是仅 API 导入；参数单位能确认 |
| 独立直流核验 | 3.3 V、10 kΩ+10 kΩ 得 1.65 V、165 µA；再并联 10 kΩ 负载得约 1.10 V，验证三个支路电流与节点关系 |
| RC 瞬态与初始条件 | 10 kΩ、1 µF、零初始、3.3 V 阶跃；10 ms 时约 2.086 V；验证重置、保存后重开、步长减半结果在事先约定容差内一致 |
| 开漏上拉 | 分别检查拉低和释放时的回路、VOL 与上升过程；说明模型电阻和电容，不能由曲线单独宣称协议通信成功 |
| 测量定义 | 区分对地电压与两点压差，确认电流方向；同名标签的电气连接行为有清晰提示 |
| 改图与撤销 | 删除、重连、复制、撤销、重做后拓扑一致；旧运行不能被标为新图的有效结果；探针指向不能悄悄换对象 |
| 文件与草稿 | 直流、带状态 RC、带模型器件分别往返；核对连接、参数、模型、初始条件和约定保留的示波器设置；历史波形不被暗示为已恢复 |
| 异常与恢复 | 理想源冲突、无效输入、空图、缺失参考等案例明确给出实际求解状态；允许修图、重试和打开上一个可用版本 |
| 预算与响应 | 用多个规模与时间尺度案例确定支持范围；超出样本/文件预算明确拒绝或停止，不截断成有效结果；单独记录无法硬中断的限制 |
| 浏览器与课程回归 | Chromium/WebKit 的鼠标、快捷键、参数输入和本地恢复；课程进度、固定模板与既有评分继续通过相关回归 |

上述数值是验收参考，不是声称沙盒已经完成验收。正式核验应先写清模型、激励、初始条件、取样时刻与容差，再记录实际结果。

## 10. 需求决策建议

接受这条新增需求，将其作为当前 MVP 的独立增量。采用“原生编辑器 + 中文项目工作台”，以小型电路的绘制、观察、复测和保存为验收目标。

它能直接补足当前课程中的迁移练习：你可以把工作原理图中的一小段等效出来，先预测，再改变一个条件查差异。工程能力的提升仍依赖对参考点、模型假设和实物规格的检查；工具应帮助把这些检查做得直观，而不是把能画出波形等同于真实设计已正确。

外部参考：[作者的模拟器使用说明](https://www.falstad.com/circuit/)介绍了颜色、电流动画、元件编辑与示例；[上游仓库的固定提交](https://github.com/pfalstad/circuitjs1/tree/8ee04b18a6c9241675f1c4f766617806c2fe148d)用于来源定位。关于本项目 API、XML 格式和集成限制的判断，以本地固定源码与本次小范围实测为准。
